# KronLLM Q10 — полная архитектурная сводка

Ниже всё, что можно проверить по коду и по собранной модели, а не по памяти:
числа посчитаны из `KronTransformer(experiment_config("Q10"))`. Сводка также
легла в репозиторий — `docs/architecture.md`, раздел 10.

## 1. Что это такое в одном абзаце

Decoder-only трансформер на 9,938,886 параметров, в котором **каждая матрица
`d → d`** (q, k, v, o и оба плеча FFN — шесть модулей на блок) является
суммой `L` каналов, каждый канал — суммой `K` произведений Кронекера, а каналы
дополнительно связаны рекуррентностью **по глубине**: состояние `D` передаётся
из блока в блок и глушится на границе каждого второго блока. Ширина 512,
25 блоков, контекст 512, словарь 8192, эмбеддинг факторизованный и связанный с
выходной головой.

## 2. Геометрия

| параметр | значение |
|---|---|
| `d_model` | 512 |
| блоков / голов | 25 / 8 (`d_head = 64`, обычный MHA) |
| контекст | 512 |
| словарь | 8 192 (BPE, цифры изолированы) |
| эмбеддинг | `8192 × 256` + `256 × 512`, голова связана с ним |
| Кронекер | `L = 4` канала, `K = 10` слагаемых, `n₁ × n₂ = 16 × 32` |
| рекуррентность | `K_win = 2`, композиция произведением, `σ` обучаемая |
| якорь | `s = 1.0`, заморожен |
| FFN | gated Kron: `silu(W_f h) ⊙ W_g h`, оба `d → d` |
| нормы | RMSNorm, плюс `qk_norm` в каждом слое |
| инициализация | `τ = 0.1`, `γ = 0.1` (ReZero), `θ ~ N(0, 0.1)` |

## 3. Математика одного модуля

Матрица `d × d` не хранится. Вместо неё хранятся факторы:

```
I_l = Σ_{k=1..K} A_lk ⊗ B_lk,    A_lk ∈ R^{16×16},  B_lk ∈ R^{32×32}
```

`A ⊗ B` не материализуется в forward: используется тождество
`(A ⊗ B) vec(X) = A · X · Bᵀ`, где `X = reshape(x, 16, 32)`.

Дальше — рекуррентность по глубине. Для блока `i` и канала `l`:

```
D_l^{(i)} = τ_l · rms_norm( Î_l + σ(θ_l) · D_l^{(i-1)} )
W_l^{(i)} = s·Id + D_l^{(i)}
P^{(i)}   = W_L^{(i)} · … · W_1^{(i)}          (композиция произведением)
y         = γ^{(i)} · P^{(i)} x
```

Четыре детали, без которых это не работает:

- **`rms_norm` по всей матрице**, а не по строкам. Без неё произведение
  схлопывается в `s^L · Id` и рекуррентность не получает градиента.
- **`σ(θ)` с `θ ~ N(0, 0.1)`** — обучаемая скорость переноса состояния
  (в среднем `|θ| ≈ 1.38` к концу обучения, `σ` около 0.8). Живёт в `theta`,
  учится с `lr = 1e-2` и `weight_decay = 0`, отдельно от матриц.
- **Якорь `s·Id`** даёт полный ранг и стабильный градиент на старте: `I_l` —
  это инновация поверх единичной матрицы, а не замена ей.
- **`K_win = 2`** сбрасывает состояние каждые два блока. Рекуррентность
  ограничена по эффективной глубине, иначе 25 блоков дают 25-кратное
  произведение и градиент умирает.

Отдельно: `rank(A ⊗ B) = rank(A)·rank(B)`, поэтому одно слагаемое с
полноранговыми факторами уже даёт полный ранг. Это **не** low-rank
приближение — экономия только в числе параметров.

## 4. Параметры (замер, а не оценка)

| компонент | параметров | доля |
|---|---:|---:|
| 150 кронекеровых модулей (6 × 25) | 7 681 350 | 77.3 % |
| эмбеддинг `E` (8192 × 256) | 2 097 152 | 21.1 % |
| проекция `U` (256 × 512) | 131 072 | 1.3 % |
| RMSNorm (2 × 512 на блок + финальный) | 26 112 | 0.3 % |
| QK-norm (2 × 64 на блок) | 3 200 | 0.03 % |
| **итого** | **9 938 886** | **100 %** |

Один модуль:

```
L·K·(n₁² + n₂²) + 2L + 1 = 4·10·(256 + 1024) + 8 + 1 = 51 209
```

Против `512² = 262 144` у плотной матрицы — **в 5.12 раза меньше параметров
при полном ранге**. Шесть ролей на блок: `q, k, v, o, f, f_g`; плотными
остаются только две матрицы эмбеддинга.

Для сравнения: плотный трансформер той же ширины и глубины потратил бы
`150 × 262 144 = 39.3M` только на матрицы — вчетверо больше, чем вся модель
целиком.

## 5. Внимание, FFN, эмбеддинг

- **Внимание.** Pre-norm RMSNorm → q/k/v из кронекеровых карт → `qk_norm` по
  каждой голове → RoPE (`θ_rope = 10 000`) → SDPA → выход через кронекерову
  `o`-карту. `qk_norm` держит операнды внимания на одном масштабе независимо
  от того, как разрослась кронекерова ветка; без него ломается `lr = 3e-4`.
  Стоит 128 параметров на слой.
- **FFN.** Гейт: `f = W_f h ⊙ silu(W_g h)`, оба плеча — кронекеровы `d → d`.
  Гейт выиграл 1.5 % bpb при равных параметрах (Q8w против Q8g), поэтому в
  Q10 он включён.
- **Эмбеддинг.** `E ∈ R^{8192×256}` и `U ∈ R^{256×512}`, логиты считаются как
  `h · Uᵀ · Eᵀ`, то есть голова связана с таблицей и не стоит ничего. Это
  2.23M параметров вместо 4.19M у плотной `8192 × 512`.

## 6. Токенизатор и данные

- **BPE на 8 192**, byte-level, обучен на 20 МБ стратифицированно по языкам и
  доменам. Каждая цифра — отдельный токен: `\d` раскалывается **до** ByteLevel
  (вариант «после» убивал кириллицу — 2.72 байта на токен вместо 4.96).
  Пять зарезервированных id: `<|system|> 8187`, `<|user|> 8188`,
  `<|assistant|> 8189`, `<|eot|> 8190`, `<|endoftext|> 8191`.
- **Корпус:** 8.62 ГБ, 968 334 документа, **2 250 807 719** train-токенов,
  EN 61.9 % / RU 38.1 % по токенам, фертильность 3.69 байта на токен.
  Held-out 46.2M токенов (2 %), стратифицирован по языку и домену.
- **Identity-слайс** — сгенерированные тексты про саму модель (1 650 уникальных
  документов на язык), апсемплинг ×8 в эпохе, без цифр, вне held-out.

## 7. Обучение

| параметр | значение |
|---|---|
| оптимизатор | AdamW |
| LR | 3e-4 постоянно всю эпоху (WSD), `θ` — 1e-2 |
| weight decay | 0.1 на матрицах, 0 на `θ` |
| clip | 1.0 |
| точность | fp16 autocast, одна T4 |
| батч | 32 × 512 = 16 384 токена на шаг |
| эпоха | 137 377 шагов = 2.2508B токенов |
| замер | 2.53 с/шаг, ~6 500 ток/с, ~95.6 GPU-ч на эпоху |
| сессии | по 500 минут, resume с `last.pt`, чекпоинт каждые 500 шагов |

Дальше — decay-проход `Q10A`: 40 649 шагов (29.6 % эпохи, ~28 GPU-ч),
LR 3e-4 → 1e-6, на отобранном миксе 666M токенов (математика 14.7 %, весь
identity-слайс до 2.5 %).

## 8. Арифметическая цена — честно

Параметры куплены **вычислениями, а не рангом**. Композиция
`P = (sI + D₄)⋯(sI + D₁)` — это `L·d³` MAC на модуль за forward: `4 × 512³ ≈
537M` MAC (1.07 GFLOP), × 6 модулей × 25 блоков = **161 GFLOP на forward** при
контексте 512.

| длина контекста | forward, MFLOP/токен |
|---:|---:|
| 128 | 1 348.6 |
| 256 | 726.0 |
| 512 | **424.5** |
| 1024 | 293.4 |

При 512 токенах прелюдия — **около трёх четвертей** forward-арифметики
(315 из 424 MFLOP на токен); тело модели (внимание, FFN, одно применение
`h @ Pᵀ`) — ~105 MFLOP на токен плюс `2·T·d` на внимание. Доля прелюдии падает
как `1/T`: на 1024 токенах это уже 157 из 293.

Именно поэтому выигрыш здесь — по памяти и по числу параметров (модель влезает
в 4 ГБ чекпоинта и в 16 ГБ T4 с запасом), а не по стоимости шага. Чтобы
получить выигрыш и по FLOPs, нужны fused-ядро для прелюдии и факторизованное
состояние рекуррентности; ни того, ни другого в этом окружении нет (Windows
PyTorch идёт без Triton, `torch.compile` недоступен).

## 9. Чего в Q10 сознательно нет

- **GQA** — `d_head = 64`, KV-кэш не является узким местом, обычный MHA.
- **Рекурсия весов / разделение блоков** — `recurse = 1`, 25 уникальных блоков.
  E2 показал, что нетренированная рекурсия деградирует (1.57 → 2.08 bpb при
  двух проходах).
- **MoE и routed-эмбеддинг** — Q3 и Q7 проиграли плотной факторизованной
  таблице (Q7: 0.9533 против 0.8489 bpb).
- **Sum / grouped / alternating композиции** — измеримо ниже эффективный ранг и
  не лучше bpb (E14/E17/E18), поэтому в Q10 продукт.
- **Dropout, gradient checkpointing, DDP** — 10M-модель этого не требует; DDP
  заблокирован не кодом, а 32 ГБ cgroup на хосте.

## 11. Что это значит на практике

9.94M параметров против 2.25B токенов — это **226 токенов на параметр**, то
есть примерно в 40 раз дальше compute-optimal. Так сделано намеренно:
параметризация интересна только тогда, когда узкое место — данные, а не
ёмкость. Отсюда и ожидания по качеству: ~0.80–0.83 bpb к концу эпохи,
~0.75–0.80 после decay-прохода. Для сравнения: gzip на тексте даёт ~2.0–2.5,
символьные n-граммы ~1.4–1.6, GPT-2-класс (124M) на английском вебе ~1.0.
