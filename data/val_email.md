# Вал, что он на самом деле меряет, и GPT-2 на том же тексте

Хороший вопрос — и ответ оказался неприятным: число `val bpb`, которое я
присылал каждую тысячу шагов, меряло **английский Python** и занижало байты
примерно на треть. Ниже разбор, замеры и что уже исправлено.

## 1. Из чего состоит вал

Held-out — 2 % корпуса, стратифицированно по языку и домену: **19 358
документов, 170.7 МБ текста, 46.2M токенов**, EN 61.9 % / RU 38.1 % (как и в
тренировочном корпусе).

| домен | токенов | доля |
|---|---:|---:|
| ru/энциклопедика | 8.97M | 19.4 % |
| en/математика | 7.23M | 15.7 % |
| en/код | 4.91M | 10.6 % |
| en/наука | 4.84M | 10.5 % |
| ru/литература | 4.82M | 10.4 % |
| en/ML | 3.33M | 7.2 % |
| en/литература | 3.24M | 7.0 % |
| en/энциклопедика | 2.65M | 5.7 % |
| ru/математика | 2.13M | 4.6 % |
| en/CS | 1.48M | 3.2 % |
| ru/наука | 1.08M | 2.3 % |
| en/логика | 0.87M | 1.9 % |
| ru/логика | 0.39M | 0.9 % |
| остальное (identity, ru/CS, ru/ML, юмор) | ~0.2M | 0.5 % |

Вот это — правильный состав. Но обучение меряло не его.

## 2. Две ошибки в числе, которое я присылал

**Ошибка первая — домен.** Вал-бин пишется по бакетам, а `en/code` сортируется
первым (en: code, cs, encyclopedic, …, science). Оценка в `train.py` — это
последовательный проход с потолком `eval_batches = 64` батча по 8 × 512 =
**262 144 токена**. То есть каждую тысячу шагов я мерил первые 0.6 % бина, а это
английский код (конкретно — исходники Twisted). Код — самый предсказуемый домен
в миксе, поэтому кривая такая красивая.

**Ошибка вторая — знаменатель.** `bits_per_byte` делит на **3.694** байта на
токен (среднее по корпусу). У кода реально ~2.67 байта на токен. Значит
заявленный bpb занижен ровно в 3.694 / 2.67 = **1.38 раза** — при том же лоссе.

Вместе это даёт искажение в одну сторону, и заметное.

## 3. Что на самом деле

Прогнал шаг 11,723 по-честному: те же токены, но с реальными UTF-8 байтами.

| спаны | Q10 (10M, шаг 11.7k) | GPT-2 (124M) |
|---|---:|---:|
| первые 1 024 блока (524k токенов, весь английский код) | **1.184** | 1.365 |
| страйд по всему бину (1 024 блока, 1.9 МБ, EN+RU, все домены) | **1.248** | 1.554 |

То есть вместо 0.884 честное число на том же коде — **1.184**. Тот же
чекпоинт на представительной выборке — **1.248**.

## 4. Разбивка по языкам (это важнее итоговой строки)

| модель | весь бин | EN | RU |
|---|---:|---:|---:|
| Q10, шаг 11.7k | **1.248** | 1.518 | **0.990** |
| GPT-2 124M | 1.554 | **1.306** | 1.792 |

Читается так: на смешанном тексте 10M-модель уже обыгрывает GPT-2 на 0.31
bpb, но **весь выигрыш — русский**. В английском GPT-2 сильнее (1.306 против
1.518), и это нормально: у неё в 12 раз больше параметров и на два порядка
больше английского текста. А на коде Q10 обгоняет GPT-2 уже сейчас (1.184
против 1.365) — код это 10.6 % нашего корпуса и почти ничего у GPT-2 в таком
виде.

Отдельно: **bpb нельзя сравнивать между языками**. На кириллице один токен —
это ~5 байт, на латинице ~2.9, поэтому русский bpb ниже при том же качестве
предсказания. Смотреть надо по столбцам, а не по итогу.

## 5. Что исправлено, чтобы это не повторялось

1. **`train.py` теперь логирует два числа**: старое `val_bpb` (последовательный
   проход, для непрерывности уже нарисованной кривой) и `val_bpb_uniform` —
   страйд по всему бину за ту же цену (512 блоков из 90 229). Конфиг Q10 и Q10A
   включают это (`training.eval_uniform`), код уже собран как
   `icold21/kron-llm-code-v14`, чейн перезапущен и поднимет следующую сессию
   с ним.
2. **`scripts/eval_reference.py`** — офлайн-замер любого чекпоинта (или GPT-2)
   на одних и тех же блоках: декодирует токены обратно в текст, считает
   настоящие байты, отдаёт bpb общий и по языкам.
3. **Чейн** после каждой сессии прогоняет этот замер на скачанном чекпоинте
   (одна минута на 1660 Ti) и кладёт результат в `data/baseline_latest.json`;
   GPT-2-эталон считается один раз и переиспользуется.
4. **Отчёт** теперь цитирует страйдовое число, а таблица сравнения с GPT-2
   попадает в каждое письмо. Старое число остаётся в отчёте отдельным
   столбцом, чтобы кривая не рвалась.

## 6. Чего ждать к концу эпохи на этой шкале

Сейчас 8.5 % эпохи и 1.248 честных. По кривой проекта (Q8g и родственники)
остаток эпохи даёт 15–20 % относительного улучшения, decay-проход — ещё 5–8 %.
Отсюда ориентир: **~1.00–1.05 к концу эпохи и ~0.95–1.00 после аннила**, при
этом EN подтянется к уровню GPT-2 (1.2–1.3), а RU уйдёт в 0.7–0.8. Это
экстраполяция по чужим кривым, не обещание; через две недели будет видно по
двум честным точкам.

Что это меняет в статье: цифры вроде «0.88 bpb на 10M» надо забыть — их не
было. Честная рамка звучит иначе и, по-моему, лучше: 10M-модель на 2.25B
токенов, обученная на 62/38 EN/RU, на смешанном тексте обгоняет GPT-2-124M
уже на 8 % эпохи, а в английском догоняет к её концу.
