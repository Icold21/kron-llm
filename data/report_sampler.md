# Q10: сэмплер данных был сломан, корпус decay собран

Сессия 6 идёт (запущена 13:55 МСК, лимит 660 мин). Ниже — что изменилось с момента
прошлого письма про корпус, потому что одна из прошлых цифр была неверной.

## 1. Сэмплер тянул 1/512 корпуса

`ByteDataset._new_epoch` переставлял **все стартовые позиции токенов** (2.78 млрд),
хотя `__len__`/`__getitem__` того же класса работают с блоками по 512 токенов.
Замер на тестовом бине: эпоха тянула 5.44 млн окон из 2.78 млрд возможных.

| | было | стало |
|---|---|---|
| покрытие эпохи | **63.2 %** (треть корпуса не читалась ни разу) | **100 %** |
| повторы внутри эпохи | ~1.58× на прочитанный токен | нет |
| перестановка | 22.3 ГБ int64 | 43 МБ |
| шагов в эпохе | 169 884 | 169 884 (не изменилось) |

Число шагов не изменилось, потому что `steps_per_epoch` всегда считался от блоков —
ломался только выбор данных. Сессия перезапущена с шага 36 549 на коде
`icold21/kron-llm-code-v20`: пропуск 21.5 % = 598.9 млн токенов, то есть ровно
столько, сколько уже пройдено. Тест `test_an_epoch_tiles_the_corpus_and_covers_it`
на старом коде падает (63 %), на новом проходит.

## 2. Seen-set: сделан, но для этого прогона ничего не меняет

Прочитанные документы теперь восстанавливаются точно: при кодировании бина
пишется `train_index.npy` (span + хэш токенов каждого документа), по диапазону
шагов переигрывается та же перестановка, и получается список документов, которые
сессия уже прочитала. Для старого бина индекс восстановлен из самого бина за 37 с
(914 861 документ).

Замер на реальном бине, 15 551 шаг (254.8 млн токенов, 9.2 % корпуса):

| | значение |
|---|---|
| документов прочитано хотя бы на 50 % | 36 592 из 914 861 (4.0 %) |
| это токенов | 33.9 млн (1.2 % корпуса) |
| «затронуто» хотя бы одним блоком | 54.6 млн токенов — удалять их было бы расточительно |

Порог `min_share` (по умолчанию 50 %) появился именно поэтому: блоки тянутся
равномерно по токенам, и длинные документы задеваются чаще коротких.

Главное: **остаток бюджета — 2.18 млрд токенов на корпус 2.78 млрд**, то есть
прочитать можно максимум 78.5 % корпуса, и позиционный пропуск 21.5 % читает
ровно 78.5 %. Для этого прогона позиционный старт и есть правильный; seen-set
пригодится при старте второй эпохи или если корпус пересобрать меньше бюджета,
и он уже готов (`--skip-seen` + `--target-tokens`).

| | значение |

| токенов | **809 120 240** |
| документов | 249 868 |
| байт на токен | 3.53 |
| доля эпохи | 29.1 % |

| held-out | тот же `a45bbb03` — bpb сравним со всей историей |

Шагов 49 384, а не «30 % эпохи»: число берётся из самого бина, чтобы данные
читались ровно один раз. Недобор до 30 % — это поставка, а не округление: у
`en/humour`, `en/identity`, `ru/code`, `ru/humour` квоты нечем закрыть.

Датасет `icold21/kron-q10a-anneal-bin` залит и прочитан обратно (809 120 240
токенов, EN 0.5998 / RU 0.4002). Ядро `kaggle/q10a` ссылается на код v21 и этот
датасет и будет запущено, как только освободится GPU-слот после сессии 6.

## 5. Что ещё нашлось

- **Чат-пулы снова стёрлись при сборке микса.** Проверка была написана через
  `Path.stem`, а он снимает только последнее расширение (`en_chat.jsonl.gz` →
  `en_chat.jsonl`), поэтому не срабатывала. Первый decay-бин вышел 782 млн
  токенов и без единого чат-токена; заметно было только по числу токенов.
  Теперь это `kronllm.bilingual.sweep_stale_mix` и три теста.
- **Kaggle не отменяет GPU-сессию при пуше новой версии ядра.** Две сессии висели
  одновременно, третий пуш отбился лимитом «Maximum batch GPU session count of 2».
  Лечится удалением ядра (чекпоинт лежит в датасете, терять нечего).
- **Лимит сессии — 12 часов.** Поставил 660 минут вместо 690: копирование бина
  занимает ~10 минут, и у ядра, убитого по таймауту, может не сохраниться вывод.
- Поправлено ложное предупреждение проверки бина: оно сравнивало `<|system|>` с
  нулём, потому что при отключённых промптах поле `already_prompted_docs` всегда 0.
